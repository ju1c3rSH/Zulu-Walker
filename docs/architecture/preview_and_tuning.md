# 预览与调参体系（MaixCAM 与 Linux 同构）

> 来源：`EOD2026-NearCam` 赛事分支的调试/调参实践提炼。
> 目的：给后续项目一套**平台无关**的预览与在线调参模式——同一套机制在 MaixCAM（MaixPy 触屏）和普通 Linux（cv2 窗口 + trackbar）上都能实现相同功能。
> 本文只描述可复用模式，不含赛事业务参数。

## 1. 两套体系与统一方向

赛事分支里并存两套、彼此零代码共享的调试体系：

| 体系 | 入口 | 渲染 | 适用 |
|---|---|---|---|
| detector debug | `run.py debug <name>` | cv2 trackbar + 桌面窗口 | 离线调参、阈值实验 |
| 页面 tuner | 主循环 `KEY_OK` 切换 | MaixPy 触屏自绘 | 设备上现场调参 |

两者重复实现了同一组骨架。统一方向：**抽公共内核，业务只注入 schema 与预览算法**。

## 2. 可复用的最小内核

以下四件是纯机制，与具体目标（色环/人质/激光）无关，应进通用框架：

1. **ConfigSchema** —— 参数定义（名称、范围、步长、奇偶数约束、raw↔显示值缩放）。统一 `ParamDef`（detector 侧）与 tuner 里手写的 sliders 列表。
2. **ParamPanel** —— trackbar/滑条 ↔ 值的双向映射，含 `raw × scale`、奇数约束。MaixCAM 与 Linux 只是 Panel 的两个后端。
3. **内容签名热重载** —— 用 `(size, sha1)` 而非 mtime 判断配置文件变化，限频轮询（约 2Hz），且**仅在读成功时缓存签名**（保证首次 SAVE 建文件必触发）。
4. **渲染基座** —— 颜色工具、命中测试 `_in`、文本/矩形绘制、native canvas 转换、toast、阶段耗时打点。

> 平台差异只体现在第 2、4 件的后端实现；第 1、3 件完全平台无关。

## 3. 必须留在项目层的部分

- 各 tuner 的**预览算法**：LAB 阈值分析、激光点检测、YOLO 推理。
- **参数 schema 的具体取值**与持久化文件键路径。
- 业务语义：坑位锁存、左右镜像、靶标/爆区 ROI、激光校零线、shape 映射。

这些是项目知识，不进通用框架。

## 4. 关键坑：mtime 同 tick 失效

**现象**：连续两次 SAVE 落在同一文件系统 tick 内，`mtime` 相同（实测 300 次写入中 187 次 mtime 一致），热重载判"未变"→ 参数不生效，表现为"SAVE 了但参数没变"。

**修法**：
- 签名改为 `(size, sha1)` 内容哈希，同长改值也能检出；
- 限频轮询到约 2Hz，避免每次 `step()` 读文件；
- 签名只在读取成功后缓存 —— 首次 SAVE 建文件必触发重载。

该范式与业务无关，是框架级价值；赛事分支最初埋在业务processor里，提炼时应上提。

## 5. 预览渲染的平台同构

- **帧格式**：统一用平台原生画布。MaixCAM 用 `FMT_RGB888`（相机原生 CMM/VIPU 直通），Linux 用 `cv2.imshow`（ndarray）。避免 `cv2image` 产生的 BGR888 在 MaixCAM `show()` 内部被整帧 `to_format(RGB888)`（实测 18~20ms vs 2~6ms）。
- **显示出口**：单一 `show()` 调用点。MaixCAM 侧是 display tap，Linux 侧是 cv2 sink；两者实现同一"呈现"协议，节流与异常隔离策略共用。
- **节流**：调参页逐帧渲染，但 show 与 HUD 绘制同频节流；页面进/出清相位，保证首帧必可见。

## 6. 赛事特化保留项（不进框架，仅记录设计意图）

以下两项留在 `EOD2026-NearCam`，**代码不动**，仅在此记录其触发条件与设计意图，供复刻时判断是否需要：

- **Rich TUI 禁用开关**：CAM1 仅 128MB 用户内存，`rich` 是纯 Python 大包。启动器按配置禁用 Rich 控制台，"是否在运行"用 `sys.modules` 查询而非直接 import，避免为一次判定把 rich 拉进内存。
- **比赛模式跳过渲染**：`competition_mode` 下跳过 HUD 绘制与推流以让出控制周期，但显示帧仍每帧发布（否则触摸退出失效、LCD 全黑）。这是赛事实时性取舍，与通用框架的呈现策略无关。

## 7. 建议的抽象边界

```
framework/                      项目层（app/ 或 modules/）
─────────────────────           ──────────────────────────
ConfigSchema                    LAB / 激光 / YOLO 预览算法
ParamPanel (Maix / cv2 后端)    具体参数取值与文件键
内容签名热重载                  坑位锁存 / 镜像 / ROI 语义
渲染基座 (颜色/命中/绘制/toast)
单一显示出口 + 节流策略
```

框架提供机制与后端，项目注入 schema 与算法。这样 MaixCAM 与 Linux 用同一套代码即可获得相同的在线调参能力。
