## 1. 问题定义

### 1.1 场景

摆杆上方摄像头以 **40–50 Hz** 运行 YOLO11n 检测钢珠，每帧给出 bbox 中心的 **X 像素坐标**。MSPM0 微控制器需要通过 UART 获取钢珠的**位置**和**速度**来做摆杆角度 PID 控制。

```
                    YOLO 检测 (40-50 Hz)
  ┌──────────┐     ┌────┐     ┌─────────────┐     UART (~500 Hz)
  │ 摄像头    │ ──→ │NPU │ ──→ │ α-β 滤波器  │ ──→ │ MSPM0 PID │
  └──────────┘     └────┘     └─────────────┘     └─────────────┘
   1280×352        每帧一次      平滑 + 速度估计       摆杆角度控制
   RGB             测量 zx                        位置 pe_x + 速度 ball_val
```

### 1.2 三重需求

| 需求 | 含义 | 挑战 |
|------|------|------|
| **位置平滑** | 消除 YOLO bbox 的 ±2–3 px 抖动 | 平滑过大会导致相位滞后，PID 不稳定 |
| **速度估计** | 从位置序列中推算速度（无法直接测量） | 差分法 `Δx/Δt` 放大测量噪声（20ms 间隔下 1px 噪声 → 50 px/s 速度噪声） |
| **帧间预测** | NPU 帧之间有 20–25ms 空窗，MSPM0 需要连续数据 | 纯外推没有反馈修正，误差会漂移 |

### 1.3 为什么不用简单方法

| 方法 | 位置平滑 | 速度估计 | 帧间预测 |
|------|:--:|:--:|:--:|
| 滑动平均 | ✓（滞后大） | ✗ | ✗ |
| 指数平滑 (EMA) | ✓ | ✗ | ✗ |
| 差分法 `Δx/Δt` | ✗ | ✓（噪声大） | ✗ |
| α-β 滤波器 | ✓ | ✓ | ✓ |

## 2. α-β 滤波器推导

### 2.1 核心状态

滤波器内部维护两个标量：

```
x̂   — 滤波后的位置估计（像素）
ẋ̂   — 速度估计（像素/秒）
t_last — 上次 UPDATE 的时间戳（纳秒）
```

每次有新的测量值 `z`（YOLO bbox 中心 X 坐标），滤波器执行两步：**PREDICT → UPDATE**。

### 2.2 为什么需要两步

假设你盯着雷达屏追踪一架飞机。每次雷达扫过屏幕你看到一个光点（测量），两次扫描之间你根据飞机的**最后已知速度**猜测它现在应该在哪里（预测），然后当下一次光点出现时，你用新光点修正你的猜测（更新）。

这就是 α-β 的核心直觉：**每个测量周期内，先推后修。**

```
  时间 →
  ════════╤═══════════╤═══════════
  t=0     │  t=0.025  │  t=0.050
  Z₀      │           │  Z₁
          │           │
  有测量  │  帧间空窗  │  有测量
  → UPDATE│ → PREDICT │ → UPDATE
          │  只外推   │
          │  不修正   │
```

## 3. PREDICT（外推预测）

### 3.1 匀速模型假设

假设钢珠在 dt 这段时间内保持当前速度不变：

```
x_pred = x̂ + ẋ̂ · dt
```

这是一个**一阶泰勒展开**：$x(t + \Delta t) \approx x(t) + \dot{x}(t) \cdot \Delta t$。高阶项（加速度 × dt²/2）在 0.025s 时间内贡献约 0.03 px，可以忽略。

### 3.2 关键设计约束

PREDICT **输出外推值，但不改变内部状态** `(_ab_x, _ab_vx)`。原因是：

```
如果 PREDICT 修改了内部状态：
  帧间预测: x̂ → x̂ + ẋ̂·dt (内部状态前移)
  下一次 UPDATE: residual = z - (被污染的内部状态)
  → 残差偏小 → 修正不足 → 累积误差
```

正确做法（代码第 619–624 行）：

```python
# PREDICT: 只外推输出值，不修改 _ab_x、_ab_vx
dt_s = (t_ns - self._ab_ts_ns) / 1e9
x_pred = self._ab_x + self._ab_vx * dt_s
return (x_pred, self._ab_vx, self._ab_locked)
# _ab_x 和 _ab_vx 保持不变 ↑
```

## 4. UPDATE（测量修正）

### 4.1 残差计算

```
x_pred = x̂ + ẋ̂ · dt           (预测值)
r = z - x_pred                (残差 = 测量 - 预测)
```

**残差 r 的物理含义**：

| r > 0 | 钢珠跑得比预测快（加速了） |
| r < 0 | 钢珠跑得比预测慢（减速了） |
| r ≈ 0 | 速度估计准确，只受测量噪声影响 |

### 4.2 位置修正（α 项）

```
x̂_new = x_pred + α · r
       = x_pred + α · (z - x_pred)
       = (1 - α) · x_pred + α · z
```

这是一个**指数加权平均**：
- α=1 → `x̂ = z`，完全信测量，不做平滑
- α=0 → `x̂ = x_pred`，完全不信测量，只用模型
- α=0.7 → 70% 信测量，30% 信预测（实现取值）

### 4.3 速度修正（β 项）

```
ẋ̂_new = ẋ̂_old + (β / dt) · r
```

这步是 α-β 区别于纯低通的核心。

**为什么除以 dt？** 残差 r 是**位置量纲**（像素），要换算成速度（像素/秒），必须除时间：

```
r = 速度误差 × dt + 位置误差
  ≈ 速度误差 × dt               （位置误差已被 α 项吸收）

→ 速度修正量 ≈ r / dt
→ 乘以 β 分配比例： ẋ̂_new = ẋ̂_old + β · (r / dt)
```

**β 的物理含义**：

| β | 含义 |
|---|---|
| 0.0 | 永远不修正速度（退化为纯 EMA） |
| 0.3 | 30% 的残差归结为速度误差（实现取值） |
| 1.0 | 100% 归结为速度误差（等价于差分法，噪声最大） |

## 5. α 和 β 的物理含义

### 5.1 阶跃响应可视化

假设钢珠从 x=0 突跳到 x=100 px 后稳定。不同 α 的收敛轨迹：

```
位置
100 ┤                    ╭──── α=0.9 (快，少平滑)
    ┤                 ╭──╯
    ┤              ╭──╯      α=0.7 (中)
    ┤          ╭──╯
    ┤       ╭─╯              α=0.4 (慢，多平滑)
    ┤   ╭──╯
  0 ┤───╯──────────────────── 时间
    0   1   2   3   4   5 (帧)
```

- α 越大 → 响应越快（滞后小），但平滑效果弱
- α 越小 → 平滑效果好（滞后大），但响应慢

### 5.2 速度跟踪可视化

```
速度                          ╱╲
60 ┤                         ╱  ╲  实际速度
   ┤                     ╱──╯   ╲
   ┤                 ╱──╯        ╲   β=0.5 (敏感)
   ┤              ╱─╯              ╲
   ┤          ╱──╯                  ╲ β=0.3 (中)
   ┤      ╱──╯                        ╲
 0 ┤─────╯────────────────────────────── 时间
   0   1   2   3   4   5   6   7   8 (帧)
```

- β 越大 → 速度跟踪灵敏，但测量噪声放大
- β 越小 → 速度平滑，但加速度响应滞后

## 6. 与卡尔曼滤波器的关系

α-β 滤波器是卡尔曼滤波器在**稳态**（增益收敛）下的特殊形式。

### 6.1 完整卡尔曼滤波器结构

```
预测步:
  x̂⁻ = F · x̂          (状态预测)
  P⁻ = F·P·Fᵀ + Q     (协方差预测)

更新步:
  K = P⁻·Hᵀ / (H·P⁻·Hᵀ + R)    (计算卡尔曼增益)
  x̂ = x̂⁻ + K·(z - H·x̂⁻)        (状态更新)
  P = (I - K·H)·P⁻               (协方差更新)
```

对于一维匀速模型：
```
状态向量:   x = [位置, 速度]ᵀ
状态转移:   F = [[1, dt], [0, 1]]
观测矩阵:   H = [1, 0]
卡尔曼增益: K = [α, β/dt]ᵀ  (当 P 收敛到稳态时)
```

### 6.2 α-β = 简化版卡尔曼

| 特性 | 卡尔曼 | α-β |
|------|:---:|:---:|
| 增益 | 自适应（从协方差 P 计算） | 固定 α, β |
| 不确定度跟踪 | 跟踪 P 矩阵 | 不跟踪 |
| 过程噪声建模 | Q 矩阵（完整） | 隐含在 α, β 中 |
| 测量噪声建模 | R 矩阵（标量） | 隐含在 α, β 中 |
| 帧率适应性 | 自动（通过 F 矩阵中的 dt） | 手动传入 dt |
| 代码量 | ~150 行 | ~50 行 |
| 调参 | Q, R（2–6 个标量） | α, β（2 个标量） |
| 适合场景 | 帧率不稳定、多传感器融合 | 帧率稳定、单传感器 |

**为什么这个项目用 α-β 而不是完整卡尔曼？**

1. YOLO 帧率稳定（40–50 Hz），增益不需要自适应
2. 只有位置测量（单传感器），没有加速度计/IMU 融合需求
3. 两个参数（α, β）的调参成本远低于 Q, R 矩阵
4. MaixCAM2 上 Python 浮点运算不占主频

## 7. 频域视角：低通 vs 预测型滤波

### 7.1 位置通道 = 一阶低通（IIR）

把 α-β 的位置更新方程写成差分方程形式：

```
x̂[n] = (1 - α) · x̂[n-1] + (1 - α) · dt · ẋ̂[n-1] + α · z[n]
```

忽略速度项（ẋ̂·dt），退化为：

```
x̂[n] = (1 - α) · x̂[n-1] + α · z[n]
```

这就是**指数移动平均（EMA）**，等价于一阶 IIR 低通滤波器。

截止频率（-3dB 点）：

$$f_c \approx \frac{\alpha}{2\pi \cdot dt} = \frac{0.7}{2\pi \cdot 0.025} \approx 4.5\text{ Hz}$$

这意味着：高于 4.5 Hz 的信号成分（主要是 YOLO bbox 抖动）被衰减。

### 7.2 完整的 α-β = 滞后补偿的低通

纯低通的问题：输出永远滞后于输入。α-β 通过速度项 **补偿了这个滞后**：

```
纯低通 (EMA):        x̂[n] = (1-α) · x̂[n-1] + α · z[n]
                                                   ↑ 无速度补偿

α-β 滤波:            x̂[n] = (1-α) · (x̂[n-1] + ẋ̂·dt) + α · z[n]
                                                ↑ 速度前推一步
```

在频域中，带速度项的 α-β 在 **3 Hz 处的相位滞后约 30°**，比同截止频率的纯低通（~45°）更小。这来自速度估计的"前瞻"效应。

### 7.3 两种滤波器的对比

| 特性 | 一阶低通 (EMA) | α-β 滤波器 |
|------|:---:|:---:|
| 传递函数分母阶数 | 1 | 2 |
| 输出 | 只有位置 | 位置 + 速度 |
| 相位滞后 @ 3 Hz | ~45° | ~30° |
| 预测能力 | 无 | 有（`ẋ̂ · dt` 外推） |
| 阶跃响应 | 指数收敛，零超调 | 可能超调（β 过大时 ±10%） |
| 稳态误差（斜坡输入） | 有 | **零** |

**最重要的一点：**

给 α-β 一个匀速输入 `z[n] = v₀·n·dt`，稳态时：
- EMA：`x̂[n] = v₀·n·dt - v₀·dt/α`（有固定滞后 `v₀·dt/α`）
- α-β：`x̂[n] = v₀·n·dt`（零稳态滞后，因为速度项 ẋ̂ → v₀ 完全补偿）

这就是 α-β 能够**零误差跟踪匀速运动**的数学原理。

## 8. 参数选择：Benedict-Bordner 关系

### 8.1 最优 α-β 配比

对于一个恒定噪声环境下的匀速目标追踪问题，Benedict 和 Bordner (1962) 证明了最优（最小化均方误差）的 α-β 配比满足：

$$\beta = \frac{\alpha^2}{2 - \alpha}$$

这等价于卡尔曼滤波器的稳态增益。

| α | Benedict-Bordner β | 适用场景 |
|:--:|:--:|------|
| 0.5 | 0.167 | 重度平滑，慢速目标 |
| 0.7 | 0.377 | 中等平滑，通用场景 |
| 0.9 | 1.012 | 快速跟踪，高噪声容忍 |

### 8.2 实现中的参数选择

当前取值 α=0.7, β=0.3，比 Benedict-Bordner 最优值（β=0.377）偏保守 20%。

**降低 β 的理由**：
- YOLO bbox 的测量噪声比雷达/激光雷达大（非高斯、可能偏置）
- 摆杆钢珠是**低速运动**（≤30 cm/s），不需要高灵敏度的速度追踪
- 保守的 β 减少速度噪声 → MSPM0 的 PID D 项输入更稳定

### 8.3 调参实验方法

**标定 α（位置平滑）**：
1. 钢珠静止在摆杆中心（已知真实位置 x_true）
2. 录 200 帧 YOLO 检测 → 计算标准差 σ_z
3. 设定目标平滑比：σ_filtered / σ_z ≈ 0.5
4. 由 EMA 的方差缩减公式反推：α ≈ 2/(1 + σ_f²/σ_z²) → 查表

**标定 β（速度跟踪）**：
1. 钢珠沿摆杆自由滚落
2. 录 50 帧 → 用 α-β 计算速度
3. 与手动标注的速度（帧间标尺读数）对比 RMSE
4. 扫描 β ∈ [0.1, 0.8]，取 RMSE 最小点

## 9. 收敛保护：LOCKED / UNLOCK 状态机

### 9.1 为什么需要收敛保护

钢珠停在目标点（±1cm 内）时，α-β 的速度估计仍然在微调：

```
每帧残差 r ≈ 0–3 px（纯测量噪声）
速度修正 = (β/dt) · r = (0.3/0.025) · (±3) = ±36 px/s ≈ ±1.4 cm/s
```

速度在 ±1.4 cm/s 之间震荡 → MSPM0 收到"钢珠在微动"的信号
→ 可能触发不必要的摆杆角度调节 → **引发真正的机械振荡**。

### 9.2 LOCKED 状态机设计

```
                          │
                          ▼
                    ┌──────────┐
            ┌──────→│ TRACKING │←────────┐
            │       └────┬─────┘         │
            │            │               │
            │     连续3帧 │vx|<25px/s    │ 单帧跳变>25px
            │            │               │ 或 累积偏置>10px
            │            ▼               │
            │       ┌──────────┐         │
            └───────│  LOCKED  │─────────┘
                    └──────────┘
                     vx = 0
                     不外推
```

**状态行为**：

| 状态 | 位置 | 速度 | 外推 |
|------|------|------|:--:|
| TRACKING | α-β 正常 UPDATE | α-β 正常 UPDATE | ✓ |
| LOCKED | 跟随测量 zx | **强制归零** | ✗ |

### 9.3 解锁策略：双路径

LOCKED 状态下有两条退出路径：

```
路径 1: 单帧跳变 (JUMP)    → |residual| > 25 px (~1 cm)
  适用场景: 摆杆突然大幅倾斜 → 钢珠瞬移
  解锁延迟: 立即 (1 帧)

路径 2: 累积偏置 (BIAS)    → |bias_sum| > 10 px (~0.4 cm)
  适用场景: 钢珠从极低速逐步加速、速度过零反向
  解锁延迟: 2 cm/s 时 ~8 帧 (约 0.2s)
```

**为什么需要路径 2？**

钢珠在速度过零点（极值点）进入 LOCKED 后，反向加速过程中的每帧位移只有 1–3 px，远达不到单帧跳变阈值 25 px。如果没有累积偏置检测，LOCKED 状态会把后续所有位移都解释为"噪声"，速度永远锁在 0。

路径 2 的累积偏置跟踪：

```python
# LOCKED 状态下每帧 UPDATE
self._ab_bias_sum += residual           # 累积每帧位移

if abs(self._ab_bias_sum) > BIAS_PX:   # 累积超出阈值
    unlock                              # 退出 LOCKED
elif residual * self._ab_bias_sum < 0:  # 方向反转（如测量噪声 ±3px）
    self._ab_bias_sum = residual        # 重置累积 → 不会误触发
```

**噪声安全性**：±3 px 的测量噪声逐帧反向 → `residual * bias_sum < 0` → 累积复位 → 永远达不到 10 px → 不会误解锁。

## 10. 帧间预测：PREDICT 与时序管理

### 10.1 数据流频率

```
  NPU 推理 (40-50 Hz)          UART 发送 (~500 Hz)
  ═══════════╤═══════════     ═══╤══╤══╤══╤══╤══╤══
  t=0        │  t=25ms           │  │  │  │  │  │  │
  UPDATE     │  UPDATE          U  P  P  P  U  P  P  P
             │                  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑
             │                  测量修正   外推预测
```

- **U (UPDATE)**：有新鲜 YOLO 检测帧 → 执行完整的 α-β UPDATE 步骤
- **P (PREDICT)**：帧间空窗 → 只执行 PREDICT 外推，不改变内部状态

### 10.2 信号区分机制

_coordinator 通过 `_ai_new` 标志区分两类调用：

```python
# _process_vision_results() — 有新 NPU 帧到达
self._ai_new = True
self._ai_seq += 1

# _build_pendulum_position_payload() — 每次 coordinator.loop() 调用
is_new_frame = self._ai_new
self._ai_new = False               # 消费标志

if is_new_frame:
    # UPDATE: 有测量值 zx → 修正内部状态
    self._ab_ball_filter_apply(cx, True, t_ns)
else:
    # PREDICT: 帧间空窗 → 只外推输出值
    self._ab_ball_filter_apply(0.0, False, t_ns)
```

### 10.3 dt 精度要求

β 项对 dt 的敏感性：

```
速度修正量 = (β / dt) · r
```

| dt 误差 | β=0.3 下对速度的影响 | 累积效果 |
|---------|----------------------|----------|
| 1% (0.25ms) | ±1% 速度修正误差 | 10 帧后速度偏差 < 0.5% |
| 5% (1.25ms) | ±5% 速度修正误差 | 10 帧后可能偏差 3–5% |

因此使用 `time.perf_counter_ns()` 纳秒级时间戳，且取自 NPU 推理完成点（`ai.py` 中 `model.detect()` 返回后立即打戳），避免 Python 层调度延迟污染 dt。

## 11. 实际工程：YOLO 检测 + α-β 的数据流

### 11.1 完整数据路径

```
  camera.read_raw()                    _process_vision_results()
  ─────────────────                    ─────────────────────────
  1280×352 RGB                         更新 _latest_ai
       │                                   │
       ├─→ _last_frame (numpy)             ├─→ _ai_seq += 1
       │                                   │
       ├─→ _last_raw (maix Image)          └─→ _ai_new = True
       │                                       │
       └─→ AIInferenceProcessor                │
            .process()                         ▼
                │                    _build_pendulum_position_payload()
                │                    ─────────────────────────────────
                ├─→ _ai.detect(raw, _raw=True)    is_new_frame = _ai_new
                │   │                                 │
                │   ├─ 推理完成打时间戳 ns              ├─→ _ab_ball_filter_apply(cx, True/False, t_ns)
                │   │                                 │       │
                │   └─→ detections[]                  │       ├─ UPDATE: x̂, ẋ̂ 修正
                │                                     │       └─ PREDICT: x_pred 外推
                └─→ filter_detections()               │
                    (面积/宽高比/边缘)                  ├─→ calib.project(cx_f, cy_f)
                        │                             │
                        └─→ pipe.last_results         ├─→ pe_x, ball_cm
                                                      │
                                                      └─→ ball_val = ẋ̂ / pixels_per_cm * 100
```

### 11.2 输出协议帧格式

```
Byte 0-1: pe_x (s16 LE)       归一化位置误差 [-5000, +5000]
Byte 2-3: ball_cm (s16 LE)    物理位置 0.01cm 单位 [-1250, +1250]
Byte 4:   flags (u8)          bit0=TARGET_FOUND
Byte 5:   reserved (u8)       恒为 0
Byte 6-7: ball_val (s16 LE)   钢球速度 0.01cm/s 单位 [-32768, +32767]
```

MSPM0 侧使用：

```c
// 位置偏差 → PID P 项
int16_t pe_x = frame.percent_error_x;

// 速度 → PID D 项 (derivative on measurement) 或速度前馈
float vel_cm_s = frame.ball_val * 0.01f;

// ball_val_valid: 由帧长度 10 字节自动推导（10 字节 = valid）
if (frame.ball_val_valid) {
    derivative_term = Kd * vel_cm_s;  // 速度前馈
}
```

## 12. 参数速查表

### 12.1 滤波器核心参数

| 参数 | 值 | 物理含义 | 选择依据 |
|------|:--:|------|------|
| α | 0.7 | 70% 信测量，30% 信预测 | 中等平滑，3 帧收敛到阶跃 |
| β | 0.3 | 30% 残差归因于速度误差 | Benedict-Bordner β=0.377，取保守 80% |
| v_min_lock | 25 px/s ≈ 1 cm/s | "已停稳"判断阈值 | 赛题 ±1cm 容差，取 1cm/s 为保守 |
| lock_frames | 3 帧 | 连续几帧低速后锁定 | 3×25ms = 75ms 消抖 |
| unlock_jump | 25 px ≈ 1 cm | 单帧跳变解锁阈值 | 对应摆杆倾斜 → 钢珠急加速 |
| unlock_bias | 10 px ≈ 0.4 cm | 累积位移解锁阈值 | >3σ 测量噪声 (~9px)，零误触发 |

### 12.2 系统物理参数

| 参数 | 值 | 说明 |
|------|:--:|------|
| 摆杆长度 | 25 cm | PPR 水管，凹槽光滑 |
| 钢珠直径 | 1 cm | 滚珠轴承钢球 |
| 像素密度 (标定) | 25.6 px/cm | 640px / 25cm，安装后实测 |
| YOLO 模型 | YOLO11n | 单类（steel ball），640×640 输入 |
| NPU 帧率 | 40–50 fps | 推理间隔 20–25ms |
| 钢珠最大速度 | 30 cm/s | 物理约束（摩擦力 + 摆杆倾角） |
| 赛题精度要求 | ±1 cm | 偏离目标点误差上限 |
